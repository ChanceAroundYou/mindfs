## 0. 一句话结论

Router 的总结问题不是「模型写得差」，而是**三处管道在写入与读出两端各砍一刀**：
写入口的规则自相矛盾（窗口内 8 条决策因此整轮被吞）、写入上限把句子从 token 中间切断、
卡片渲染层把 Markdown 抹平并夹到 3 行；而「反复总结」是**每个回合都无条件覆盖卡片**造成的，
与去重护栏（只在同一回合内生效）根本不搭。

## 5. 建议改法（具体到规则 / 提示词 / 流程，含取舍）

按「止血 → 去重 → 格式」排优先级。每条都标注是否需重启。

### S1 修规则冲突（对应 R3 + R4）— **最高优先，需重启**

**做法（推荐 A）**：允许 `[say, ask_user]` 同轮，顺序固定 say 在前。

- 工具层：`ask_user` 仍然是唯一允许「执行动作」的独占动作，但可与一个 `router_say` 同轮；
  `router_silent`、`run_workflow`、`message_agent` 等仍必须单独。
- 提示词规则 5 改为：「`router_silent` 必须单独使用；`router_ask_user` 可与一个 `router_say` 同轮
  （say 写结论，ask 写选择题），但不能再带任何执行动作。」
- 规则 18 末条保持不变（它表达的产品意图是对的）。
- 应用层：先写 say 活动、再建提问卡，顺序固定（`created_at` 单调）。

**取舍**：新增一种合法组合，需要补校验矩阵与测试（含「say + ask + run_workflow」仍整轮拒）。
风险是同一轮两条活动的先后渲染，可用固定顺序消除。

**备选 B（零代码，只改提示词）**：有决策事项时 summary 只写一句结论，单独下一轮 `ask_user`。
取舍：用户会看到两条消息；Router 每轮 3 回合预算多消耗一格，可能与巡检抢预算。**作为 A 的回退。**

### S2 拒绝不吞文字（对应 R4）— 需重启

非法动作仍然拒，但若决策里含纯文本 say，就把它按 summary 应用，并写一条可见系统行
`route-rejected:<decision>:<seq>: <原因>`（**该机制已存在**，G-QE 就为巡检回合做过同样的可见拒绝）。

**取舍**：与「半套动作比没有动作更危险」的原则有冲突，因此只放行**纯文本**，
任何有副作用的动作（`run_workflow` / `cancel_*` / `retry_*` / `set_node_model`）仍然整轮拒绝。

### S3 截断不再切在 token 中间（对应 R1）— 需重启

- `cutAtSentence` 只在「句末标点 + 后随空白/换行/结尾」处切；找不到就退到最近换行，再退到 `runes[:limit]➕…`。
- 上限从 600 抬到 **1000**（与 Router 输入侧 excerpt 上限同口径），并**保结构优先**：
  截断时优先保留最后一整段以 `**` / `-` / `没做` / `未验证` 开头的块，而不是单纯按字数。

**取舍**：卡片文字变长，但卡片本来就只显示 3 行，长出来的部分只在详情与 `title` 里；
详情可读性提升是净收益。抬上限会让 `result_summary` 变大（最多 ~1 KB/任务），可接受。

### S4 「实质变化」才覆盖卡片（对应 R5）— 需重启

判据（全部机械可判，不调模型）：本轮 `tool_calls == 0` **且** 新 summary 与上一条 summary 的
字符三元组 Jaccard > 0.6 **且** 没有新的用户留言/提问作答 → 记为 `progress` 而不是 `summary`，
卡片保持上一条实质结论。

批处理方式：宁可漏降级（误把有变化的降成 progress，用户仍能在会话里看到）也不误顶卡片。

**取舍**：需要新判据与测试；风险是「简短但有实质结论」的回合被降级——用 `tool_calls==0` 兜住大部分。

### S5 巡检零变化不出声（对应 R6）— 需重启

巡检回合（`task_orphaned` / `turn_stalled` / `turn_interrupted` 触发）若状态与上一次同类巡检相同，
直接 `silent`；同一任务同一 `kind` 的「无变化」文本 30 分钟内去重（按归一化文本 hash）。
被拒动作仍走 S2 的可见行，不会因此变成静默。

**取舍**：用户可能担心「Router 是不是死了」——用任务卡片上的巡检角标（已存在）承担可见性。

### S6 输入侧头尾各取一段（对应 R7）— 需重启

`excerpt` 改为「首 500 + 尾 500」，中间用 `…（中间省略 N 字）…`。理由：结论段几乎总在开头，
待办与未验证常在结尾。备选是**在结算回合强制 Router 读一次会话**（`router_read_session`），
但会把每轮延迟再加 3–10 s（实测 Router 回合 6–130 s 不等），不作为默认。

**取舍**：样本实测只有 3 个回合（#96 18:02、#68 09:13、#68 10:55），是否所有 worker 报告都头重尾重
未验证；作为保守改动可先上，再按现场调比例。头尾拼接口径要在测试里钉死（中间省略标记必须出现，
避免 Router 把两段当成连续文本）。

### S7 总结允许四个「标签行」（对应 R2）— 需重启

把四段改成固定标签行，标签内允许列表与行内代码、禁止表格：

**改前**（当前规则 18）：「按四段写：结论 / 证据 / 没做或未验证 / 下一步，每段一到两句，总长 200–400 字…」

**改后**：
```
结论：<一到两句>
证据：<逐条列，可用 - 列表与行内代码；不要表格>
没做或未验证：<逐条列>
下一步：<一句话，需要用户决定就写清要定什么>
```
硬上限 800 字（卡片另做截断）。**卡片 3 行也至少能看到「结论：」这一句。**

**取舍**：四个标签占约 20 字；需要同步前端卡片剥离 `**`/反引号（见 S8），否则符号更显眼。

### S8 卡片渲染与详情一致（对应 R8）— **纯前端，不需要重启**

卡片对 `result_summary` 复用 `stripMarkdown`（`notify/plaintext.go` 已有实现，前端可照抄一份纯函数），
或改为渲染受限 Markdown（仅粗体/行内代码/列表）。存量 #103 那条也会立刻正常显示。

**取舍**：纯展示改动，风险最低；本组里唯一可以「不批后端、先做前端」的一条。

## 6. 待批准的选项

**选项 1（推荐）｜先止血：S1 + S2 + S3 + S6**
只做「用户根本看不到 / 看到了但被截断」这两件。规模最小、收益最直接：8/8 被吞的告警与根因能落地，
卡片不再切在 IP 端口中间，Router 能看到报告的结论段。

**选项 2｜只修「反复总结」：S4 + S5**
不动格式与截断，只让「没推进」不再顶掉实质结论、巡检不再刷屏。
适合「先别动总结内容，先把噪音降下来」。

**选项 3｜只修格式：S7 + S8（+ 可选 S3）**
卡片能读、详情有结构。不含 S1，所以规则 18 与规则 5 的矛盾仍在——带选择题的优质总结还会被整轮吞掉。

**选项 4｜整套采纳：S1–S8，拆 3 次提交依次过门禁**
先 S1+S2（校验/应用层），再 S3–S7（写入与输入），最后 S8（前端）。每组各自跑
`go test -count=1 ./...`、`tsc`、Vitest、`make check-upstream`，并按项目规则登记 `Scope: G-X`。

> 不批准任何一项 = 维持现状；本轮不改产品、不提交、不部署。
