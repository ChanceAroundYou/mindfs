# 后端文件长度与拆分（长期规则）

- **口径**：物理行数，以 `wc -l` 计。
- **软线**：300 行。超过后应在本次工作中判断职责边界并记录明确拆分安排；后续改动不得把它当作无限期搁置的理由。
- **硬线**：500 行。超过必须在合并前拆分。
- **适用范围**：`server/` 与 `cli/` 中所有手写 Go 文件，**包括测试文件**；不按测试、目录或历史状态区分。
  生成产物应放在源码目录之外。

## 超了怎么拆

1. 按 handler 或用例职责拆文件，保持同一领域的实现相邻。
2. 大型 service 按游标、同步、绑定、搜索等内聚子逻辑拆分。
3. 纯类型与常量放入职责明确的模块，避免为了行数拆散紧密协作的代码。

执行原则：小批拆分并运行 `make test`；改动 SQLite 前先说明回滚方式。
