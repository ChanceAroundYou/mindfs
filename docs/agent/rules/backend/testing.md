# 后端测试规范（长期规则）

- 位置：与被测文件同目录 `xxx_test.go`；契约测试（如 `workspace_test.go` 的共享实例/分区断言）
  是防退化的另一半，删测试即删约束。
- 命令：`make test`（Go 全量）。改 `ws.go` handler 后必跑对应包测试 + 手查 goroutine 派发。
- 新增 handler/usecase 必须同批加测试；`role_test.go`（控制面表）、`workspace_test.go`
  （账户分区）、`startup_config_test.go`（启动配置）三类契约测试不许降级为跳过。

```bash
make test                 # Go 全量
go test ./server/internal/api/...   # 单包
```

## 验证测试守得住：变异必须因正确原因变红

「注入一个已知错误改法 → 测试变红」只证明**有东西红了**，不证明红在那条改法上。同一批
输入经常有多条守卫，去掉一条会让另一条接手，测试照样红 —— 报「已变异验证」而实际守的是
别的分支。

- **断言失败原因**，不只断言失败。去掉形状检查后改由「版本不一致」拒绝时，测试若只写
  `if err == nil` 就永远绿；要断言错误文本里出现「形状」这类判据词。
- **变异时必须 `-count=1`**。Go 测试缓存不追踪测试里 `exec` 出去的非 Go 输入
  （2026-11-23 实测：脚本改成 `exit 1`，不带 `-count=1` 仍报 `(cached)` 且绿）。
  `scripts/mutate.sh` 已带，手搓的变异 run 别忘了加。
- 变异**还原后再跑一次**确认复绿；只删注入不重跑，等于没验「红是注入引起的」。
