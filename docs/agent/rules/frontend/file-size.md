# 文件长度与拆分（长期规则）

- **口径**：物理行数，以 `wc -l` 计。
- **软线**：300 行。超过后应在本次工作中判断职责边界并记录明确拆分安排；后续改动不得把它当作无限期搁置的理由。
- **硬线**：500 行。超过必须在合并前拆分。
- **适用范围**：`web/src/` 内所有手写 `.ts` 与 `.tsx` 源文件，统一适用，不按路径、内容类型或历史状态区分。
  构建产物放在输出目录，不作为源码维护。

## 超了怎么拆（判据优先级）

1. 文件里有多个命名 export 时，按职责拆分，每个模块有清楚的职责和入口。
2. 单一 export 但包含多个内部子职责时，按函数与数据的内聚关系拆兄弟模块，原文件只保留编排。
3. 组件文件可将子组件、逻辑、样式和纯函数分别移到合适模块。
4. hook 文件可按子流程拆分，原 hook 只负责组合调用。

执行原则：小批拆分并做类型检查与相关测试，保持行为不变，并遵循既有源码映射测试方式。
