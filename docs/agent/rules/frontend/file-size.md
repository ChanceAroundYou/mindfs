# 文件长度与拆分（长期规则）

- **口径**：物理行 `wc -l`，CI 一条命令可卡。
- **红线**：软 300（超了记 TODO，下次触及时拆）/ 硬 500（必须拆，进清单）。
- **豁免**：`i18n/locales/*.ts`（纯数据）、`*.d.ts`、生成物、`main.tsx`（入口）。
- **清单型豁免**：同质化呈现资源簇（如 `components/task/taskIcons.tsx` 的图标与任务徽标样式）可超线，但必须文件头列出导出清单和归属理由。

## 超了怎么拆（判据优先级）

1. 文件里有 2+ 个命名 export → 按 export 拆，每个新文件一个主 export。
2. 单 export 但有多个内部子职责（按函数名聚类）→ 按职责拆兄弟文件，原文件留编排。
3. 组件文件 → 子组件拆出、逻辑拆 `useXxx.ts`、样式拆 `xxxStyles.ts`、纯函数拆 `xxxUtils.ts`。
4. hook 文件 → 按子流程拆兄弟 hook，原 hook 只做组装调用。

执行原则：每次 2–3 个 + 一次构建，零行为变化，遵循既有 workflow（source-map 读层、TDZ 判据）。
