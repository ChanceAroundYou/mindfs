# 对话式任务系统

## 概述

MindFS 的任务系统采用**对话式交互**：你发送一条留言，Agent 自动选择合适的
Workflow 执行，并把结果作为一条回复返回。任务详情面板不再是一张需要逐段推进的
阶段表，而是一条可以持续对话的时间线。

一次任务的基本循环：

1. 创建任务，写下初始目标。
2. 在任务详情面板里继续发留言，补充需求、回答问题或要求返工。
3. Agent 每次执行完都会给出一条总结回复；需要时可展开执行详情追到具体节点或会话。

## 创建任务

1. 在看板或工作台点击「新建任务」。
2. 输入任务名称和初始描述（例如「请实现用户登录功能」）。
3. 「立即执行」默认打开：提交后任务出现在看板上、自动打开详情面板，首条留言马上交给 Router。
4. 关掉「立即执行」再提交：任务只落卡停「未开始」，首条留言以「待执行」排在对话流里；
   之后点这条留言气泡上的「立即执行」才开始运行（暂停中的排队任务点「恢复」同样会派发）。

两个面板按各自需要配置，不再一刀切：

- **新建任务面板**：控件行里是「立即执行」图标开关、「选择工作流」（可选「自动」或指定某个
  workflow 版本）、「+ 附件」、「发送」。「立即执行」只留图标（悬停/读屏有完整文案），
  外观与发送键同款：28×28、8px 圆角方块，可用时同一套强调色。
- **任务详情面板**：控件行里只有「选择工作流」「+ 附件」「发送」——留言一律立刻发出，
  没有「立即执行」。派发排队留言的入口在气泡本身：待执行的留言气泡页脚带一颗
  「立即执行」，点它把这条留言交给 Router。

工作流选择随留言一起落库（`workflow_choice` / `workflow_version_id`），排队路径下也会在
派发时按留言行恢复，不会重新问一遍。指定了 `specified` 却没带版本在建卡时就返回 400，
不留一张点了「立即执行」才报错、每次点都报同一句的卡。

## 与任务对话

### 发送留言

在任务详情面板底部的输入框里输入需求，然后点「发送」或按快捷键。常见留言：

- 「请修复登录功能的 bug」
- 「给这个模块补单元测试」
- 「这个实现太慢了，优化一下」

发送成功后留言立刻出现在对话流里。Agent 还没产出正文时，回复位置显示
「等待回复…」/「正在回复…」占位；任务本身的状态只显示在详情面板标题栏。
状态不会逐条挂在每条消息上。

### Workflow 选择

输入框上方有三个选项：

| 选项 | 行为 |
|---|---|
| **自动选择**（默认） | Agent 根据留言内容自动挑选最合适的 Workflow，并在发送前给出推荐提示。 |
| **指定工作流** | 手动挑选一个已发布的 Workflow 版本。 |
| **禁用工作流** | Agent 直接响应，不启动 Workflow。适合只需要一句回答、不需要多步执行的场景。 |

### 面板顶部

详情面板的 header 分三块：

- **左侧**：任务状态、`#编号`、任务名，任务名右边紧跟编辑（铅笔）键。名字太长时只把
  名字省略成 `…`，编辑键始终在同一行。
- **中间**：留白。
- **右侧**：当前状态下真正可用的动作图标（平铺一行，含删除）→ 关闭（×）。

动作不收起、不折叠，有几项就画几项；删除也是同一排里的普通一键，不再单列。按状态：

| 状态 | 按钮 |
|---|---|
| 完成 / 取消（失败同列） | 返回、归档、删除 |
| 已归档 | 返回、取消归档、删除 |
| 待审阅 | 完成、取消 |
| 执行中 | 中断 |
| 待开始 | 开始 |
| 已暂停 | 恢复 |

「返回」走 `reopen`（已归档的任务会同时清掉归档标记）；「开始」走 `RunNow`，派发建卡时
排队的那条留言。卡片上的「收尾 worktree」不在详情里，worktree 清场仍从卡片发起。
点 × 或点遮罩都走同一条关闭路径，改名改到一半会先问一句「是否放弃修改」。

移动端与桌面是同一套结构；手机上正文的左右留白比桌面更窄（8px vs 14px），
消息卡片因此能多占一点宽度，表格与代码块仍在正文内部横向滚动，不会撑出页面级横滚。

### 查看任务状态

任务级状态在详情面板标题栏（未开始 / 执行中 / 待你处理 / 已完成 / 失败等），
对话流里的回复只展示内容本身：

- **执行中**：回复正文会显示「步骤 i/n: 节点名称」。
- **已完成**：展示本次执行的总结。
- **失败 / 已取消**：保留错误或取消原因，不会伪装成成功。

### 查看执行详情与监管记录

详情面板里有两个**始终存在**的小胶囊按钮，排在同一行、展开互斥（点开一个会收起
另一个），左边的人字箭头 icon 展开时旋转 90°，表明当前展开的是哪个：

- **执行详情**（两端同一顺序：在对话流与输入框下方）：
  - Workflow 任务：展开后查看 Workflow 的节点树、每个节点的执行状态，并能从节点跳到该节点的会话。
  - 直连对话任务：直连本身就是一种节点，按同样的节点行展示「直连对话」与任务状态；
    点节点行右侧的会话图标进入任务主会话（工具调用等执行过程都在那里），不再另写提示文案。
- **监管记录**：Router 自己重试、唤醒或交给用户处理的只读记录；没有记录时展开只显示一句空态说明。

回复如果来自某个 Agent 会话，卡片页脚还会有「打开会话」，可以直接进入对应会话。

### 消息类型胶囊

每条消息的页脚、时间前面都有一枚浅色类型胶囊，说明这条消息是什么：

| 胶囊 | 来源 |
|---|---|
| 留言 | `user_message`（存量阶段任务转换出来的是 `user_comment`，同样显示「留言」） |
| 回复 / 结果 / 进度 / 总结 / 对话 | `agent_reply` 的 `purpose`：缺省或 `reply` / `result` / `progress` / `summary` / `chat` |
| 系统 / 提醒 | `system_event` / `attention` |
| 合并冲突 | `merge_conflict` |

这是**类型**，不是状态：任务级状态只在详情面板标题栏，不逐条挂。问答卡与审批卡
本身就是带标题的卡片，不再重复加类型胶囊。

### 回到底部

对话很长、往上翻历史之后，输入框上方会出现一颗圆形「回到底部」按钮（与会话页
同一颗）；点一下逐帧收敛到最新消息。它只在离底部超过 200px 时出现——任务详情的
输入框就在对话末尾，阈值太小会让按钮在刚打开、刚落到最新消息时就亮着；用户自己
上滚或按上翻键会立刻取消收敛，不和手势抢位置。移动端与桌面端是同一颗按钮、
同一个位置（面板正文底部居中）。

### 打开即落在最新消息

打开任务详情时，面板直接滚到**真正的底部**：对话末尾的最新一条回复、底部输入框，
以及桌面端位于对话下方的两个胶囊与收尾区，全都在视口内——只对齐对话末尾会把胶囊
留在视口之外，「回到底部」也就不到底。滚动只在首屏数据到齐的那一刻发生一次：
之后的新留言、流式回复都不会把正在上翻历史的用户拉回底部；切换任务会重新落到底部。

输入框与下方胶囊之间只留 6px（`回到底部` 浮层与滚动锚点都是零高度且不吃间距），
底部不再多出一段空白。

移动端与桌面同一顺序：两个胶囊排在对话流（含输入框）下方、收尾区上方，就是普通的
流内内容。面板落到最新消息时它们正好在视口内；往上翻历史时跟着内容一起走，
不会停在顶部变成一条吸顶横条，也不遮挡对话。输入框长高时由贴底对齐把面板底部钉住，
胶囊既不跟着上浮、也不会被顶出视口。间距与滚动目标在两种宽度下是同一套规则
（`web/src/index.css` 里 `.task-detail-execution` 只有 `min-width`，任何断点都不改
`order` / `position`）。

## 历史任务

阶段模型已在 2026-11-12 被**整体替换**，并在 2026-11 把阶段概念从任务类型、API 与前端里
**彻底删除**：不存在兼容视图，新建任务也不再携带任何阶段流水（只收一条用户留言，
之后每轮由 Router 决定走 workflow 还是直连回复）。历史阶段任务在服务启动
（或显式运行转换脚本）时一次性转成对话 + WorkflowRun：

- 第一段用户输入变成一条 `user_message` 活动；
- 后续每个阶段变成 WorkflowRun 里的一个节点，节点的状态与时间取自原阶段运行；
- 原阶段会话仍可通过回复卡片上的「打开会话」进入；
- 任务详情统一渲染对话视图，不再有「历史阶段视图」入口。

旧行会先备份到 `tasks_backup_legacy_stages` 与 `stage_runs_backup_legacy`，
原始 `stage_runs` 也保留为只读审计证据。转换是单向的，回滚只能从备份恢复。
完整规则、状态映射与回滚步骤见 [`docs/migration/stages-to-conversation.md`](../migration/stages-to-conversation.md)。

## 快捷键

新建任务面板、任务详情输入框与会话输入框共用同一套回车语义
（`web/src/shared/sendShortcut.ts` 的 `resolveEnterIntent`），不各写一份：

| 快捷键 | 作用 |
|---|---|
| `Ctrl/Cmd + Enter` | 发送当前留言（桌面与移动端都可用） |
| `Enter`（桌面） | 换行，不发出去 |
| `Enter`（移动端） | 默认换行；在侧栏「通知」面板打开「回车发送」后改为发送 |
| 自定义发送快捷键 | 侧栏偏好里设定后优先于 `Ctrl/Cmd + Enter` |
| `Esc` | 关闭浮层 / 面板（有未保存修改时会先确认） |

移动端默认不让回车直接发送，但发送键始终可用（有文字或附件即可点），
「回车发送」只是可选偏好，不会出现「只能靠回车、按钮又点不到」的死角。

## 相关接口

前端对话流依赖以下 REST 端点（均按 `root_id` 分片，并跟随账户的 `user=` 分区）：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/tasks/{id}/activities?root_id=...` | 获取任务的活动流 |
| `POST` | `/api/tasks/{id}/activities` | 创建留言并触发 Agent 回复 |
| `GET` | `/api/tasks/{id}/activities/{activityId}?root_id=...` | 获取单条活动 |
| `GET` | `/api/workflows/available` | 列出可自动选择的 Workflow |
| `POST` | `/api/workflows/recommend` | 根据留言推荐 Workflow |

WebSocket 会推送 `task.activity.created` 与 `task.activity.updated`，所以同一个任务
在其它窗口或设备上的新留言与状态变化会自动出现，无需手动刷新。
