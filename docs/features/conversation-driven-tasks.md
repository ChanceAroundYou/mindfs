# 对话式任务系统

## 概述

MindFS 的任务系统采用**对话式交互**：你发送一条留言，Agent 自动选择合适的
Workflow 执行，并把结果作为一条回复返回。任务详情面板不再是一张需要逐段推进的
阶段表，而是一条可以持续对话的时间线。

一次任务的基本循环：

1. 创建任务，写下初始目标。
2. 在任务详情面板里继续发留言，补充需求、回答问题或要求返工。
3. Agent 每次执行完都会给出一条总结回复；需要时可展开执行详情追到具体节点或会话。

## 创建任务

1. 在看板或工作台点击「新建任务」。
2. 输入任务名称和初始描述（例如「请实现用户登录功能」）。
3. 提交后任务会出现在看板上，并自动打开详情面板。

任务创建后状态是「未开始」；发送第一条留言或在新建面板勾选「立即执行」后开始运行。

## 与任务对话

### 发送留言

在任务详情面板底部的输入框里输入需求，然后点「发送」或按快捷键。常见留言：

- 「请修复登录功能的 bug」
- 「给这个模块补单元测试」
- 「这个实现太慢了，优化一下」

发送成功后留言立刻出现在对话流里，Agent 的回复会先以「等待中」出现，随后变为
「执行中」，最后变成「已完成」或「失败」。

### Workflow 选择

输入框上方有三个选项：

| 选项 | 行为 |
|---|---|
| **自动选择**（默认） | Agent 根据留言内容自动挑选最合适的 Workflow，并在发送前给出推荐提示。 |
| **指定工作流** | 手动挑选一个已发布的 Workflow 版本。 |
| **禁用工作流** | Agent 直接响应，不启动 Workflow。适合只需要一句回答、不需要多步执行的场景。 |

### 查看进度

Agent 执行期间，回复卡片会实时显示进度：

- **等待中**：留言已提交，正在准备执行。
- **执行中**：回复正文会显示「步骤 i/n: 节点名称」。
- **已完成**：展示本次执行的总结。
- **失败 / 已取消**：保留错误或取消原因，不会伪装成成功。

### 查看执行详情

当一次回复对应了 Workflow 运行时，卡片上会出现「查看执行详情 →」：

- 查看 Workflow 的节点树；
- 查看每个节点的执行状态；
- 从节点跳到该节点内部的会话，继续查看完整上下文。

回复如果来自某个 Agent 会话，还会出现「打开会话」，可以直接进入对应会话。

## 历史任务

阶段模型已在 2026-11-12 被**整体替换**，不存在兼容视图。历史阶段任务在服务启动
（或显式运行转换脚本）时一次性转成对话 + WorkflowRun：

- 第一段用户输入变成一条 `user_message` 活动；
- 后续每个阶段变成 WorkflowRun 里的一个节点，节点的状态与时间取自原阶段运行；
- 原阶段会话仍可通过回复卡片上的「打开会话」进入；
- 任务详情统一渲染对话视图，不再有「历史阶段视图」入口。

旧行会先备份到 `tasks_backup_legacy_stages` 与 `stage_runs_backup_legacy`，
原始 `stage_runs` 也保留为只读审计证据。转换是单向的，回滚只能从备份恢复。
完整规则、状态映射与回滚步骤见 [`docs/migration/stages-to-conversation.md`](../migration/stages-to-conversation.md)。

## 快捷键

| 快捷键 | 作用 |
|---|---|
| `Cmd/Ctrl + Enter` | 发送当前留言 |
| `Esc` | 关闭浮层 / 面板（有未保存修改时会先确认） |

## 相关接口

前端对话流依赖以下 REST 端点（均按 `root_id` 分片，并跟随账户的 `user=` 分区）：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/tasks/{id}/activities?root_id=...` | 获取任务的活动流 |
| `POST` | `/api/tasks/{id}/activities` | 创建留言并触发 Agent 回复 |
| `GET` | `/api/tasks/{id}/activities/{activityId}?root_id=...` | 获取单条活动 |
| `GET` | `/api/workflows/available` | 列出可自动选择的 Workflow |
| `POST` | `/api/workflows/recommend` | 根据留言推荐 Workflow |

WebSocket 会推送 `task.activity.created` 与 `task.activity.updated`，所以同一个任务
在其它窗口或设备上的新留言与状态变化会自动出现，无需手动刷新。
